Docker/HTTPS 生产部署没有在本环境验收。工具执行前的人类审批尚未开发完成；成果版本审核、任务取消和未知副作用的事后核对不能冒充执行前审批。当前实现也不包含 QM 内核、mailbox、任意外部进程监管或商业 Worker Marketplace。

## v0.10 已保存的工作

- 房间/Agent 稳定会话身份与独立任务执行账本；领取事务内的单写入者约束。
- 已完成任务的精确宿主检查点作为后续任务候选；任务自身恢复优先；角色、技能、团队授权、资料和背景变化使旧原生上下文失效。
- Codex 适配器核验真实返回的 native session ID；不能静默新建会话后宣称续接。
- 未知外部结果在普通取消后仍阻塞后续任务；经授权核对或带说明终止后才允许新上下文工作，不复活旧任务。
- 真实协调计划产生的委派关系、分页历程和只读 HTTP 接口；执行记录弹窗显示这些服务端数据。

具体协议见 [v0.10 契约](workspace-contract-v0.10.md)。界面中的“接着上次工作”表示本次领取时的服务端续接决定，必须结合宿主回执确认实际执行。

## 启动和接续

克隆仓库后先用 `main`，Windows 双击 `start-windows.cmd`，或按 README 创建虚拟环境并运行 `python -m studio.server --port 8765`。页面“连接 Agent”接入调用方的已登录 Codex 或其他宿主；空的网页服务本身不会执行模型任务。

开发分支必须使用独立的绝对 `STUDIO_DATA_DIR` 测试，先备份再做任何数据迁移。不要向公开仓库提交本机业务数据、访问凭据或浏览器登录状态。后续接手者应先读本文件、`AGENTS.md` 和 `docs/product-scope.md`，核对实际分支与测试证据，再继续开发。
