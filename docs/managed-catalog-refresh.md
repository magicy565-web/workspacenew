# Managed executor role discovery

The explicit local-owner “connect Codex” action grants that managed process access to the current workspace's Agent directory. The local process manager refreshes **only that registered worker's** role list every 3 seconds. An idle worker polls ready work every 3 seconds, so a new role normally becomes eligible within 6 seconds, plus request and scheduling time. A busy single worker finishes its current task before claiming another. This does not add parallel execution or long-lived Agent sessions.

The managed configuration sets `follow_registered_agents: true`. The worker then omits the claim's `agent_ids` filter, using the service's existing registered allowlist. This option requires an existing `STUDIO_WORKER_SESSION`; it never automatically registers. The public worker protocol remains unchanged. External and explicitly filtered workers retain their original fixed allowlist. Setting this flag on an external worker cannot add roles to its registration, change capabilities, or grant access to a different workspace.

Catalog updates are authorized by the in-memory local manager record, not by a flag in an HTTP request or an uploaded configuration. Every refresh validates the original token's current execute scope, workspace ownership and local management permission; local anonymous mode must still be unconfigured. It then binds the exact stored workspace directory and verifies the same still-live worker session in the write transaction. The transaction changes only `agent_ids_json`. It does not renew registration expiry, change session tokens/capabilities, re-register a disconnected worker, alter tasks, or revive old leases. Context variables are restored after success and failure.

Role removal affects future claims only. Legitimately held work continues to be governed by the existing task lease and team membership rules. Removing a team member or cancelling a run still invalidates the relevant leases; adding the role back or refreshing the catalog cannot undo that cancellation. No public role-deletion API is added by this change.

A revoked/replaced/expired session, revoked bearer token, lost owner permission, transition out of local mode, or catalog over the existing 100-role registration limit stops managed catalog refresh and the associated managed process. No replacement registration or process is automatically created. Temporary SQLite/storage errors delay discovery without extending authorization or expiry. The normal worker heartbeat still owns the 90-second registration lifetime and existing task lease renewal. The manager's periodic refresh is not an OS process supervisor and does not survive a server restart.

Worker registration and bearer tokens remain in the parent worker only; the model command receives neither token environment variable nor lease credentials in its input. The added subprocess test uses an explicitly labelled protocol fixture, records a real child PID and assigned Agent ID, and persists the exact input via real HTTP/SQLite. It verifies transport and discovery, not model intelligence or Teamily algorithm equivalence.
