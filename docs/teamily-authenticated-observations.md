# Teamily 登录后的产品观察

观察日期：2026-11-03，Asia/Shanghai。经用户完成登录后，实际可操作的独立 Edge 已从登录页进入 `https://teamily.ai/chat`。本记录来自登录后的可见界面和实际点击结果，不再仅依赖公开脚本或登录前页面。右侧应用内浏览器的 URL 没有被用作自动化会话已登录的证据。

本次没有发送消息、发布分享、邀请他人、修改已有成果或购买服务。原账户内容只用于检查控件及其相互关系；截图留在本机研究目录，包含账户内容，不进入源码、公开报告或交付 ZIP。未导出 Cookie、登录令牌或个人会话正文。

后续为核对真实新群界面，新建了一个仅选择两名 AI 的独立验证群，没有选择人类联系人，也没有提交聊天消息。创建后原站自动加入引导 Agent、写入系统建立记录并展示欢迎内容。这次新增群组与前面的只读观察分别记录。

## 已观察的交互

| 入口 | 实际观察 | 对当前项目的影响 |
| --- | --- | --- |
| 聊天 | 窄全局导航、会话列表、对话正文；成果卡片包含版本、预览、收藏、分享、下载及打开 Studio；执行过程入口与正文分开 | 保持对话、执行记录和成果为有关联的不同对象，不能用静态进度占位代替执行 |
| Agent 模式 | 打开输入框模式控件，三项的可访问名称为 Instant（快速回复）、Auto（系统选择模式）、Agentic（自主规划多步骤） | 这是运行模式，不是已证明的具体模型或业务角色路由算法；当前项目的显式角色/协调者 DAG 不自动等同于它 |
| 成果库 `/artifacts` | 全部、我创建的、收藏；分类包含 Websites、文档、媒体、消息、会议；筛选维度为文件类型、修改时间、创建人、来源会话 | 成果需要跨对话检索、来源回链及类型化视图；当前项目仅覆盖其中一部分 |
| 成果卡片与媒体预览 | 卡片可回来源会话、发送到聊天；点击图片成果打开媒体预览，提供分享链接、分享给联系人、下载 | 媒体查看器与 Studio 是不同入口；看见分享按钮不等于完成了分享发送验证 |
| Studio | 从聊天的成果卡片进入，左侧保留对话，右侧大预览；可打开评论面板；顶部有版本历史、刷新、缩放、全屏、分享、关闭及跟随入口 | 应围绕“会话→成果→版本→反馈→修改”设计连贯体验，不能只拼出相似卡片 |
| Studio 版本 | 实际打开版本菜单，当前样本显示 v2；菜单说明切换的是 Studio 预览 | 不能仅凭 v2 标签声称所有历史版本都可访问；本次未验证另一历史版本的加载结果 |
| Studio 评论 | 面板显示未解决评论；独立输入区和“评论”提交按钮；另一处显示选中数量及“发送给 Agent”；浮动工具区包含浏览、评论、标注 | 评论保存、选择讨论、交给 Agent 应是不同动作。当前 v0.7 已独立实现文字评论闭环；本次没有在原站写评论或触发 Agent 修改 |
| 智能体目录 | 行业分类、搜索、创建者筛选、角色卡片和聊天入口 | 不能把几个内置角色称为原站全目录或复制其私有提示词 |
| 创建入口 | “创建我的智能体”打开统一创建弹层，具有 Artifacts、智能体、AI 团队三个页签；智能体页提供自然语言创建输入与模板目录 | 我们现有结构化 Agent 表单尚不等同于这套自然语言创建过程；生成配置必须可审阅、可持久保存再生效 |
| AI 团队创建 | 切换团队页签，显示行业筛选、搜索、带成员头像的团队卡片及创建按钮 | 可复用的成员集合需要与固定步骤工作流分开建模；当前固定 DAG 模板不应被宣称为团队会话能力 |
| 新建群聊 | 在聊天侧栏的创建菜单进入，自定义群组可选择 AI、填写名称；实际提交两名 AI 后得到独立持续群聊，系统创建记录与引导内容出现在消息区 | 我们自己的空群必须有真实的成员/创建上下文；不能为了模仿引导内容而伪造一次模型回复 |

原站实际操作中，通知横幅会遮挡创建弹层顶部页签；关闭横幅后才可正常点击。截图前应等待异步加载和过渡结束，否则骨架屏、旧控件或半透明过渡不能作为最终设计证据。

## 会话工作台的视觉结构

在实际 1440px 视口里，原站使用约 72px 的全局导航和约 350px 的会话窗格。窗格顶部是搜索与创建；条目通过复合头像、名称、末条消息与时间表达具体对象。右侧是有整体边界的浅色会话画布，上方为成员群头，下方为持续可用的输入区。新建验证群也保留这一结构，而不是回到居中问候加工作流推荐卡。

这说明主设计目标应是会话对象与协作者身份的连续性。我们在零历史状态下列出实际已注册 Agent，是基于当前数据模型的独立首用设计；本次没有观察一个全新 Teamily 账户，不能把该适配称为原站首次注册流程。通知、积分、促销、计费与通话入口不会仅为视觉接近而加入未实现控件。

## 尚未证明的机制

本次界面观察没有揭示 Teamily 的服务端路由策略、隐藏系统提示、私有记忆算法、多人实时编辑一致性、外部工具权限实现或生产恢复算法。可见的跟随头像、版本菜单及模式控件仅证明入口存在，不证明对应后端协议。需要继续用独立的测试内容验证创建、执行、修改、恢复及多人权限，再逐项标记差异。

开发优先级：完成已落地的执行恢复整合验收；将团队成员/长期会话与工作流步骤分离；随后补自然语言创建的可审阅配置及成果库类型化导航。自动化、连接器和记忆还需登录后专项观察。已有 [公开客户端研究](teamily-client-observations.md) 和 [QM 审计](qm-implementation-audit.md) 继续作为不同层级的证据，不能混称为私有后端复刻。
