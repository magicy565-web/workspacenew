## 当前目标：M1 + M2

先证明一个企业用户能够通过专业 Agent 团队完成一次海外买手开发任务，获得可检查的成果，并在同一会话继续下一步。M3 的授权上下文和 M4 的持久任务、失败恢复、关键动作审批的基础能力同步完成。Marketplace 和第三方商业网络不进入当前交付范围。

## 首个业务验收流程

1. 用户提供企业、产品范围、目标买手市场和本次任务边界。
2. Sourcing Manager 规划并委派 Buyer Researcher、Supplier Researcher、Verification Agent；Outreach Agent 负责获授权范围内的开发材料和沟通步骤。角色不必对应不同模型实例。
3. 研究结果保存来源链接、采集日期、公司与联系人证据，并区分公开事实、卖方声明和推断。缺失信息直接说明。
4. Verification Agent 核对候选，输出可追溯的名单与排除理由。模型自评不能代替来源验证。
5. Outreach Agent 交付开发信草稿及拟执行动作。发信、联系客户、报价和费用必须先经过 Human Approval；审批对象包含确切接收方、内容、预算和有效期。输入改变使旧审批失效。
6. 获授权后，实际执行器执行并保存结果。未知外部结果须核对，不能自动重复。审批与完成是两种状态。
7. 用户在同一会话补充要求，Agent 基于已保存的事实、成果和结果继续，保留成果身份与版本来源。

验收关注真实候选、可追溯证据、可下载成果和获授权的执行记录。客户回复与成交依赖外部业务事实，不能作为模型保证的结果。

## 界面与后续阶段

Conversation 是中心。右侧 Mission / Context / Deliverables 展示实际任务、授权资料和交付物；专业团队成员可以加入会话。Canvas 仅在业务网络规划需要时打开。模型、工具、记忆、权限和执行引擎具备真实后台能力后再提供相应入口。

- M3：完善授权的共享记忆与资料隔离。
- M4：扩展持久 Mission、重试、执行前审批和预算治理。
- M5：第三方 Personal Agent / Worker 注册、委派与执行服务交易。
- M6：买手、工厂、渠道和采购业务闭环。
